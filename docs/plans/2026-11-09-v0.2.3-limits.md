# v0.2.3: budgets, token limits and request limits

> Steps use checkbox (`- [ ]`) syntax for tracking. Follow the rules in AGENTS.md.

**Goal:** an operator can cap what each user, team and key spends in USD and tokens, and how many requests they send, with the shared profile format, and callers get clear answers and headers when they hit a limit.

**Architecture:** `internal/limits` holds the counters behind a `Store` interface (a memory store now; SQL and Valkey later), with fixed calendar windows for `per_day`/`per_month`, GCRA for rates and a semaphore for concurrency. A `Limiter` resolves a caller's profile and budgets, reserves before the call (estimated input plus the output cap), and settles to the real usage after it; a failed call settles to zero. The server admits each call after it knows the model and before it calls a provider, lowers output caps in the body, and settles in `record`. At start the counters for the current day and month are seeded from the usage table, so a restart does not reset spend.

**Tech Stack:** Go 1.26, standard library. No new dependencies.

**Spec:** [docs/design.md](../design.md) sections 10 and 15, and mothership's `docs/scale.md` sections 2 to 4.

## Global Constraints

- Answers when a limit is hit: 429 `rate_limited` with `Retry-After`; 429 `concurrency_limited`; 402 `quota_exceeded` for a spent token allowance; 402 `budget_exceeded` for a spent USD budget, naming the subject, the limit and the reset; 400 `input_too_large`. All in the caller's dialect (Anthropic 402 is `billing_error`, 429 `rate_limit_error`).
- `RateLimit-Policy` and `RateLimit` headers (IETF draft structured fields), for the request rate and the token rate when they are set: `RateLimit-Policy: "requests";q=60;w=60`, `RateLimit: "requests";r=59;t=1`.
- Periods are UTC calendar days and months. Rates are `N/s`, `N/m`, `N/h`, `N/d`.
- Profiles: `profiles`, `default_profile`, `profile_bindings` (`key:`, `user:`, `team:` in that order of precedence), or `profiles_file` pointing at the shared file. Keys under `llm.` and `requests` are read; `tools.`, `agent.`, `memory.` are ignored; any other `llm.` key is a config error.
- `budgets` as in design section 10 (`user:*`, `user:<id>`, `team:<name>`, `key:<name>`; `daily`, `monthly`). `llm.cost_usd` in a profile is a budget on the caller.
- Estimates never undercount non-Latin text: ASCII at four characters a token, every other character one token each.
- Reasoning tokens are counted apart where the provider reports them apart and billed at the output price.
- Overshoot: with one replica and the memory store, a limit can be passed only by the difference between reservations and real usage of calls in flight. Documented.

## Review Focus

1. Concurrent calls cannot all pass a nearly spent allowance: reservations count before the calls finish.
2. A call that fails, or a request rejected after admission, gives its reservation and its concurrency slot back.
3. Thai text is not undercounted by the estimator.
4. A restart keeps this month's spend.
5. A caller with no profile and no budget sees no change in behaviour.
