# v0.2.4: fallback with a cooldown, and `GET /v1/usage`

> Steps use checkbox (`- [ ]`) syntax for tracking. Follow the rules in AGENTS.md.

**Goal:** when a route's first target is down, rate limited or cannot take the request, the call is served by the next target, and a target that keeps failing is skipped for a while. Callers can also ask what they have spent and what is left.

**Architecture:** the router returns a plan, the route's targets in order with the ones in cooldown moved to the end, and learns the outcome of each attempt. Each handler runs its existing path once per target until one answers. An attempt reports back before anything is written to the caller, so a failure before the first byte falls back and a failure after it does not. The limiter gains a read-only view of a caller's counters for `GET /v1/usage`.

**Tech Stack:** Go 1.26, standard library. No new dependencies.

**Spec:** [docs/design.md](../design.md) sections 6, 7, 10 and 15.

## Global Constraints

- Fall back on connection errors, timeouts, 408, 429, every 5xx, 529, and 401 or 403 from the upstream (`provider.Error.Retryable`), on a stream that fails before its first event, and on a target that cannot take the request (`provider.ErrUnsupported`, or content the translation cannot carry).
- Never fall back on another 4xx, after the caller has left, or after the request deadline. No retry of the same target.
- Cooldown: after `settings.cooldown_failures` (3) failures in a row a target is put last for `settings.cooldown` (30s). It is still tried when every other target has failed. State is kept per process, keyed by provider and upstream model. A success clears it. A target that cannot take a request is not counted as failing.
- One usage record per call, for the target that answered or the last one tried, with `fallbacks` set to the number of targets that failed before it.
- `X-Transponder-Provider`, `X-Transponder-Model` and `X-Transponder-Fallbacks` on every routed response.
- When every target fails, an upstream failure wins over an incompatible request: the caller gets the upstream error, and the 400 that names the problem only when no target was tried upstream.
- Limits reserve against the first target's price and settle at the real cost.
- Coverage at 80% or more. One PR from `feat/fallback`, then release v0.2.4.

## Review Focus

1. A stream never falls back after its first byte reached the caller.
2. A caller's own bad request (400, 404, 422 from the upstream) is never retried on another provider.
3. A caller who disconnects, or a request past its deadline, does not walk the remaining targets.
4. A reservation is settled once, at the cost of the target that answered.
5. A tool call id from Gemini still matches its result when the next turn falls back to OpenAI.
